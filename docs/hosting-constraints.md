# قيود الاستضافة المشتركة وبدائلها

| المتطلب | ما لا تدعمه الاستضافة غالبًا | البديل المنفّذ |
|---|---|---|
| تتبع لحظي بـ WebSocket | عمليات دائمة/منافذ مفتوحة | الجهاز يرسل دفعات HTTP كل ~30–60 ث (قابل للضبط)، واللوحة تستعلم كل 10 ث. `is_live` يصبح false عند قدم الموقع. |
| Queue workers | لا daemons | `bin/cron.php` كل دقيقة (تصعيد SOS، SMS، تنبيهات التوقف، الاحتفاظ). |
| Push فوري | قد يُحجب | Push اختياري (FCM) + polling + SMS تنبيه. |
| root / اعدادات PHP | غير متاحة | لا نعتمد إلا على PHP 8.1+ وامتدادات شائعة (pdo_mysql، mbstring، fileinfo، zip اختياري للـ XLSX). |
| Triggers/صلاحيات DB | قد لا تتوفر | سلسلة تجزئة للتدقيق (ADR 0006). |

## مقارنة خيارات التتبع اللحظي العالي (للاعتماد قبل أي تنفيذ)
| الخيار | التكلفة | التعقيد | متى |
|---|---|---|---|
| **HTTP polling/batch (المنفّذ)** | منخفضة جدًا | منخفض | حتى عشرات المركبات؛ تأخير 10–60 ث |
| SSE من PHP | منخفضة | متوسط (يستهلك عملية PHP لكل متصفح؛ مرفوض غالبًا) | غير موصى به مشتركًا |
| خدمة منفصلة (VPS صغير + WebSocket/Mercure) | VPS ~5–10$/شهر + صيانة | عالٍ (نشر، شهادات، مراقبة) | مئات المركبات أو تأخير <5 ث |
| Firebase Realtime/Firestore للمواقع | حسب الاستخدام | متوسط + تبعية Google | بديل للـ WebSocket دون خادم، لكن يخرج بيانات المواقع إلى طرف ثالث (يتطلب قرارًا خصوصيًا) |

**التوصية:** ابدأ بالمنفّذ؛ انتقل لخدمة منفصلة فقط إذا أثبت الاختبار الميداني حاجة لتأخير أقل.
