# خطة الاختبار وقبول المستخدم

## آلي (CI)
- PHPUnit على MySQL: مصادقة/قفل/MFA/تدوير الرموز، RBAC والنطاقات، آلة الحالات، التعارضات، تعدد المهام برحلة واحدة، idempotency (أحداث/GPS/SOS/صور)، التوقفات والانحرافات (بما فيها خارج الترتيب)، العداد (انخفاض/استثناء/صورة/معلق/تبديل مركبة)، SOS (offline/تصعيد/دورة حياة)، SMS (حالات منفصلة)، الاحتفاظ، تقارير وتصدير، XSS/CSRF، عزل السائق/المدير.
- Android core: الوصول، التوقف، backoff، أولوية outbox، سياسة التتبع، انتقالات محلية، العداد.
- فحص أسرار (gitleaks) وملفات ممنوعة، `composer audit`.

## يدوي ميداني (قبل الإنتاج) — معايير القبول الحرجة
| # | السيناريو | المتوقع |
|---|---|---|
| 1 | سائق يرى مهام غيره؟ | 404/لا يظهر |
| 2 | مدير بنطاق فريق A يفتح مهمة فريق B | 403 |
| 3 | قبول مهمة قبل إدخال العداد | يبدأ GPS فورًا؛ «قراءة معلقة» |
| 4 | قطع الإنترنت 10 دقائق أثناء الحركة | تستمر النقاط محليًا؛ اللوحة تعرض «آخر موقع قبل X» لا مباشرًا |
| 5 | عودة الاتصال | لا تكرار نقاط/أحداث؛ تعارض الإلغاء يظهر |
| 6 | مهمتان في رحلة | المسافة والتوقفات لا تتضاعف؛ إنهاء واحدة لا يوقف التتبع |
| 7 | تبديل مركبة | مرحلتان بقراءتي عداد + سجل اعتماد |
| 8 | صورة عداد إلزامية دون إنترنت | «محفوظة محليًا» ثم «وصلت» |
| 9 | SOS دون إنترنت | «بانتظار الاتصال»؛ لا يظهر للمدير حتى الوصول؛ التصعيد بعده |
| 10 | إيقاف قسري/توفير بطارية | التحذير الصريح؛ فجوة في المسار لا موقع مزيف |
| 11 | بطارية 8 ساعات تتبع | قياس استهلاك وضبط `gps.poll_interval_s` |
| 12 | تدوير/إبطال رمز، تعطيل سائق | الرموز تبطل فورًا |

## قبول المستخدم (المرحلة 8)
على staging ببيانات صناعية: تنفيذ الجدول أعلاه مع مراقبة، ثم توقيع قبول مكتوب قبل أي إنتاج.
